# دليل الأدوات — مركز تدريب ترسانة الإسكندرية

هذا الدليل يشرح الملفّين التنفيذيّين الموجودين في **جذر مجلد المشروع**:

| الملف | ماذا يفعل |
|---|---|
| `مزامنة-الغياب.bat` | يأخذ بيانات الطلاب والغياب من نظام «السستم» ويرفعها إلى قاعدة بيانات الموقع. |
| `نشر-التحديثات.bat` | يفحص الموقع ويبنيه ثم يرفع أي تعديل إلى الإنترنت تلقائيًا. |

كلاهما يُشغَّل **بالنقر المزدوج** فقط — لا حاجة لأي أوامر.

---

## أولًا: المتطلبات (مرة واحدة فقط)

1. **Node.js** — من <https://nodejs.org> (اختر نسخة LTS). لازم للملفّين معًا.
2. **Git** — من <https://git-scm.com/download/win>. لازم لملف النشر فقط.
3. **مفتاح service_role** — لازم لملف المزامنة فقط (الشرح بالأسفل).

---

## ثانيًا: ملف `مزامنة-الغياب.bat`

### ما الذي يفعله بالضبط؟

1. يفتح قاعدة بيانات «السستم» (`data\school.db`) **للقراءة فقط** — لا يعدّل فيها حرفًا واحدًا.
2. يحدّد السنة الدراسية النشطة (مثل `2026/2027`) ومداها الزمني حتى تاريخ اليوم.
3. **يرفع الطلاب**: يطابق كل طالب بالرقم القومي أولًا، وإن غاب فبرقم الملف. الموجود يُحدَّث، والجديد يُضاف. لا يتكرّر أحد.
4. **يرفع سجلات الغياب**: يرفع فقط أيام الغياب والعذر (الحضور لا يُرفع توفيرًا للمساحة — الأصل أن الطالب حاضر).
5. **يحسب ملخّص الحضور** لكل طالب: إجمالي أيام الدراسة الفعلية، وأيام الحضور، وأيام الغياب، والنِّسب المئوية.
6. **يسجّل عملية المزامنة** في جدول `import_batches` حتى يظهر في لوحة الإدارة من نفّذ ومتى.
7. يكتب تقريرًا مفصّلًا في `tools\logs\`.

> **مهم:** «يوم الدراسة الفعلي» يُحسب بنفس منطق السستم تمامًا:
> ليس جمعة، وليس يومًا في تقويم الإجازات، وليس يوم راحة أسبوعية لهذا الصف/التخصص.

### خطوات التشغيل

1. انقر نقرًا مزدوجًا على `مزامنة-الغياب.bat`.
2. **في أول تشغيل فقط** سيطلب منك مفتاح `service_role`:
   - ادخل إلى <https://supabase.com> ← افتح مشروعك.
   - من القائمة اليسرى: **Project Settings** ← **API**.
   - انزل إلى قسم **service_role** واضغط **Reveal** ثم **Copy**.
   - الصق المفتاح في النافذة السوداء (بالزر الأيمن للفأرة أو `Ctrl+V`) واضغط Enter.
   - سيُحفظ في `tools\.env.sync` ولن يسألك مرة أخرى.
3. انتظر حتى تظهر رسالة `[DONE] Sync finished successfully.`
4. اقرأ التقرير العربي الظاهر في النافذة، ثم اضغط أي زر للإغلاق.

### ⚠ عن مفتاح service_role

- هذا المفتاح **يفتح قاعدة البيانات بالكامل** ويتجاوز كل قواعد الحماية.
- **لا يُوضع أبدًا** داخل مجلد `src` ولا في ملف `.env` بجذر المشروع — كل ما في هذين المكانين يصل إلى كل زائر للموقع.
- مكانه الوحيد هو `tools\.env.sync`، وهذا الملف مُستبعَد في `.gitignore` فلن يُرفع إلى GitHub.
- لا ترسله عبر واتساب أو البريد. لو تسرّب: **Project Settings ← API ← Reset** لإبطاله، ثم أعد إدخال الجديد.

### تجربة بلا كتابة (وضع المعاينة)

لمعرفة ما سيحدث **قبل** أن يحدث:

1. أنشئ اختصارًا لملف `مزامنة-الغياب.bat` (زر أيمن ← إنشاء اختصار).
2. زر أيمن على الاختصار ← **خصائص** ← في خانة **الهدف** أضف في آخر السطر مسافة ثم `--dry-run`.
3. شغّل الاختصار. سيقرأ ويحسب ويطبع التقرير كاملًا **دون كتابة أي شيء** على الموقع.

### ملف الإعدادات `tools\sync.config.json`

يُنشأ تلقائيًا عند أول تشغيل. تفتحه بالمفكرة (Notepad) وتعدّله عند الحاجة:

| المفتاح | المعنى | القيمة الافتراضية |
|---|---|---|
| `schoolSystemPath` | مسار مجلد SchoolSystem على هذا الجهاز | `C:\Users\Target\Desktop\السستم\SchoolSystem` |
| `academicYear` | `"active"` = السنة النشطة في السستم، أو اسم صريح مثل `"2026/2027"` | `active` |
| `syncStudents` | رفع بيانات الطلاب مع الغياب | `true` |
| `includeStudentStatuses` | حالات الطلاب التي تُرفع | `["active","suspended"]` |
| `statusMap` | تحويل حالات الغياب: `sick`/`excused` ← عذر، `loss` ← غياب | كما هي |
| `excludeCalendarDayTypes` | أنواع أيام التقويم التي لا تُحتسب دراسة | كل الأنواع |
| `excludeFriday` | استبعاد الجمعة من أيام الدراسة | `true` |
| `specializationAliases` | مرادفات أسماء التخصصات (انظر أسفل) | `{}` |
| `batchSize` | عدد الصفوف في كل دفعة رفع | `500` |

> **إن غيّرت `schoolSystemPath`** فاكتب الشرطة المائلة العكسية مضاعفة داخل ملف JSON، هكذا:
> `"schoolSystemPath": "D:\\السستم\\SchoolSystem"`

### مشكلة التخصصات غير المطابقة

أسماء التخصصات في «السستم» ليست حرفيًا نفس الأسماء في الموقع. مثال:

| في السستم | في الموقع | النتيجة |
|---|---|---|
| `بناء سفن` | `بناء السفن (البدن)` | ✅ يطابق تلقائيًا |
| `تركيبات كهربية1` | `التركيبات الكهربائية` | ❌ لا يطابق (كهربية ≠ كهربائية) |

كل تخصص لا يُطابَق يظهر في التقرير كتحذير، ويُترك حقل التخصص للطالب **فارغًا** (بقية بياناته تُرفع كاملة). لإصلاح ذلك اختر أحد الحلّين:

- **الحل أ** — أضف التخصص في لوحة إدارة الموقع بنفس الاسم تمامًا.
- **الحل ب** — افتح `tools\sync.config.json` واكتب المرادف:

```json
"specializationAliases": {
  "تركيبات كهربية1": "التركيبات الكهربائية",
  "تركيبات كهربية2": "التركيبات الكهربائية",
  "تركيبات كهربية3": "التركيبات الكهربائية",
  "لحام وقطع بالغاز1": "اللحام والقطع بالغاز"
}
```

الجانب الأيسر: الاسم كما في السستم. الجانب الأيمن: الاسم أو الـ `slug` كما في الموقع. ثم أعد التشغيل.

### معاني رسائل الخطأ

| الرسالة | السبب | الحل |
|---|---|---|
| `[ERROR] Node.js is not installed` | Node غير مثبَّت | ثبّته من nodejs.org ثم أعد التشغيل |
| `لم يُعثر على قاعدة بيانات السستم في: ...` | مسار السستم خاطئ | صحّح `schoolSystemPath` في `sync.config.json` |
| `تعذّر فتح قاعدة بيانات السستم بأي طريقة` | القاعدة مقفولة أو الوحدات ناقصة | أغلق نظام السستم ثم أعد المحاولة، أو شغّل `npm install` داخل مجلد SchoolSystem |
| `لا توجد سنة دراسية نشطة في السستم` | لا توجد سنة مفعّلة | فعِّل السنة من إعدادات السستم |
| `لم يُعثر على SUPABASE_URL أو SUPABASE_SERVICE_KEY` | ملف المفاتيح ناقص | احذف `tools\.env.sync` وشغّل الـ bat ليسألك من جديد |
| `HTTP 401` أو `HTTP 403` | المفتاح خاطئ أو مُبطَل | انسخ مفتاح `service_role` من جديد بعد حذف `tools\.env.sync` |
| `HTTP 404` | الرابط خاطئ | تأكد أن `SUPABASE_URL` يطابق رابط مشروعك |
| `فشل رفع دفعة غياب` | انقطاع الشبكة أو تعارض بيانات | راجع السجل في `tools\logs\` ثم أعد التشغيل — العملية آمنة للتكرار |
| `طالب بلا رقم قومي ولا رقم ملف` | بيانات ناقصة في السستم | أكمل رقم الملف أو الرقم القومي للطالب في السستم |
| `جدول attendance ... لا يحتوي أي سجل` | لم يبدأ تسجيل الغياب اليومي بعد | طبيعي في بداية العام — لا شيء لتفعله |

> **العملية آمنة للتكرار:** يمكنك تشغيل المزامنة عشر مرات في اليوم بلا خوف — لا تتضاعف البيانات، فكل صف يُحدَّث في مكانه.

### جدولة المزامنة يوميًا (Task Scheduler)

1. اضغط `Win + R` واكتب `taskschd.msc` ثم Enter.
2. من اليمين: **Create Basic Task…**
3. **Name:** `مزامنة غياب الموقع` ← Next.
4. **Trigger:** اختر **Daily** ← Next ← حدّد الوقت (مثلًا **3:00 م** بعد انتهاء اليوم الدراسي) ← Next.
5. **Action:** اختر **Start a program** ← Next.
6. في **Program/script** اضغط **Browse…** واختر ملف `مزامنة-الغياب.bat`.
7. في **Start in (optional)** اكتب مسار مجلد المشروع (المجلد الذي يحوي الملف) — هذه الخانة مهمة، بدونها قد تفشل المهمة.
8. Next ← علّم **Open the Properties dialog** ← Finish.
9. في نافذة الخصائص:
   - تبويب **General**: علّم **Run whether user is logged on or not** وعلّم **Run with highest privileges**.
   - تبويب **Settings**: علّم **Run task as soon as possible after a scheduled start is missed** (ليعوّض التشغيل إن كان الجهاز مغلقًا).
   - اضغط OK وأدخل كلمة مرور ويندوز إن طُلبت.
10. للتجربة فورًا: زر أيمن على المهمة ← **Run**.

> عند الجدولة ستبقى النافذة مفتوحة في النهاية بسبب أمر `pause`. إن أزعجك ذلك، أنشئ نسخة من الـ bat واحذف منها سطر `pause` الأخير، وجدول النسخة.

## ثالثًا: ملف `نشر-التحديثات.bat`

### ما الذي يفعله بالترتيب؟

1. يتأكد من وجود **Node** و **Git**.
2. يتأكد أن المستودع مربوط بـ GitHub، ويضبطه إن لم يكن.
3. يسألك عن اسمك وبريدك لتوقيع التعديلات (مرة واحدة فقط، ومحليًا لهذا المشروع).
4. يثبّت الحزم (`npm ci`) إن كان مجلد `node_modules` غير موجود.
5. **يفحص الأنواع** (`npm run typecheck`) — لو فيه خطأ برمجي **يتوقف ولا ينشر**.
6. **يبني الموقع** (`npm run build`) — لو فشل البناء **يتوقف ولا ينشر**.
7. يجمع كل تعديلاتك؛ وإن لم يكن هناك جديد يخبرك ويخرج.
8. يسألك عن وصف التعديل (اتركه فارغًا ليكتب: `تحديث الموقع — التاريخ والوقت`).
9. يسحب آخر نسخة من GitHub (`pull --rebase`) لتفادي التعارض.
10. يدفع التعديل، ثم يعطيك رابط متابعة النشر ورابط الموقع.

> النشر يستغرق عادة **دقيقة إلى ثلاث دقائق** بعد الدفع، وتتابعه من:
> <https://github.com/mohameddeldawly-code/trb-training-center/actions>
>
> والموقع على:
> <https://mohameddeldawly-code.github.io/trb-training-center/>

### معاني رسائل ملف النشر

| الرسالة | السبب | الحل |
|---|---|---|
| `[ERROR] Git is not installed` | Git غير مثبَّت | ثبّته من git-scm.com |
| `[ERROR] npm ci failed` | الإنترنت مقطوع أو الحزم تالفة | تحقق من الاتصال، أو احذف `node_modules` وأعد التشغيل |
| `[STOPPED] There is a code error` | فشل فحص الأنواع | لم يُنشر شيء. اقرأ اسم الملف والسطر في الرسائل أعلاه وأصلحه |
| `[STOPPED] The build failed` | فشل البناء | لم يُنشر شيء. راجع الرسائل أعلاه |
| `[INFO] No updates to publish` | لا يوجد تعديل جديد | كل شيء منشور بالفعل — لا شيء لتفعله |
| `[STOPPED] Merge conflict` | شخص آخر عدّل نفس الملفات | اتبع الخطوات الأربع المكتوبة في النافذة، ثم أعد التشغيل |
| `[ERROR] The push failed` | إنترنت أو صلاحيات أو تسجيل دخول مُلغى | تعديلك محفوظ محليًا بأمان — أعد تشغيل الملف |

> **طمأنة:** هذا الملف **لا ينشر شيئًا إن كان في الموقع خطأ**. الفحص والبناء يسبقان الدفع دائمًا، فلا يمكن أن ينكسر الموقع المنشور بسبب تشغيله.

## رابعًا: أين تُحفظ الملفات؟

```
المنصة\
├─ مزامنة-الغياب.bat          ← انقر مزدوجًا للمزامنة
├─ نشر-التحديثات.bat          ← انقر مزدوجًا للنشر
└─ tools\
   ├─ sync-attendance.mjs      ← محرّك المزامنة (لا تعدّله)
   ├─ sync.config.json         ← إعداداتك (يُنشأ تلقائيًا · لا يُرفع)
   ├─ .env.sync                ← المفتاح السرّي (لا يُرفع إطلاقًا)
   ├─ .env.sync.example        ← نموذج للاسترشاد
   ├─ اقرأني-الأدوات.md        ← هذا الدليل
   └─ logs\                    ← تقارير كل عملية مزامنة (لا تُرفع)
```

الملفات الثلاثة `.env.sync` و `sync.config.json` و `logs\` مُستبعَدة في `.gitignore`، فلن تصل إلى GitHub أبدًا.
